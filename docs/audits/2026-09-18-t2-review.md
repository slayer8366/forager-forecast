Two places where the dispatch's words left a reading to the builder, both disclosed in the report,
both worth an owner's word before the pipeline runs on real data:

1. **The duplicate key has no taxon.** `duplicate_key()` (filters.py:114-122) is observer, 0.1 degree
   cell and day. That is the T2 dispatch's wording ("duplicates of the same observer, cell and day")
   read literally. The T1 dispatch's matching filter is "keep one record per taxon, cell and day". On
   an all-fungi pull of 2.5 million records, an observer who logs a chanterelle and a bolete in the
   same cell on the same day keeps one of the two, whichever comes first in the file, so the final
   stage of the count table will understate every group by an amount that depends on file order.
   The code matches the dispatch; the question is whether the dispatch meant it. Proposed fix: owner
   rules whether the key includes the taxon (genusKey, or the accepted taxon key); if yes, one line in
   `duplicate_key()` plus one test row.
2. **A date-only first of month counts as a default date** (filters.py:78-97: "2024-09-01" is dropped,
   "2024-09-01T13:24:27" is kept). The T1 dispatch says "first of month at 00:00:00"; the T2 dispatch
   says "default first-of-month dates". The builder's 900-record sample had 7 date-only records and 0
   at T00:00:00, so the step will bite on few iNaturalist records either way.

## 10. Gaps: gap, and the stop is the one the spec justifies

What the dispatch asked for that the report does not evidence, and why:

- **The count tables.** Not produced; need the download; the download needs GBIF credentials
  (techdocs api-downloads, quoted in the report; anonymous POST 403, reproduced). Blocked on the owner.
- **The GBIF DOI.** None; no download exists.
- **The sampling seed.** The report gives the test's seed (20260918) but does not fix the seed for the
  real draw. Fixing it now, before any candidate is seen, is what makes the draw a test rather than a
  search; it costs one line. Proposed fix: the owner or builder records the seed in the report's
  successor or as a constant beside SAMPLE_SIZE before the pull runs. Reported, not fixed: it touches
  a result.
- **The CSV.** Not produced; its population is not on GBIF and the iNaturalist pull awaits a ruling.
- **The person-only hand check.** Waits on the CSV.
- **Not checked in the report:** nine items, all stated plainly (download API acceptance, DWCA column
  names, eventDate shape, identifiedBy first-or-last, other publishers' wording, photos, sample
  representativeness, private-geoprivacy count). The reviewer adds: whether `identifications=most_agree`
  on the iNaturalist API means what the query assumes (not checked by either party); the
  count table has no publisher dimension (check 6).

Is the stop justified? Yes. SPEC.md Constraints: "Bulk record pulls go through GBIF downloads ... The
iNaturalist API is for counts and spot checks only." The dispatch's verify-first item 1 says "If GBIF
does not carry what is needed, say so and propose the smallest iNaturalist pull that does", which is
what happened. START_HERE.md "Who decides what" sends anything touching licences or scope to the owner
as a proposed row; the iNaturalist pull and the extra publishers are both there. Building the pipeline
against fixtures while blocked is within the dispatch's "Then build" and left nothing to undo.

The builder's three proposals, assessed: (a) the one-query iNaturalist pull is a proposal in text
with a matching dict in code and no caller; the count 17,165 was the only request made against that
population beyond three spot records, and no pull file exists on disk. Correctly left to the owner.
(b) DWCA is not a proposal; it is a format decision the implementer owns under "Who decides what",
made for a stated reason the reviewer confirmed on the source page, disclosed, and pinned by a test.
Holds. (c) The two extra publishers are reported, not acted on; the pipeline passes every publisher
through the same steps and the register is the gate before use. Correctly left to the owner, with the
correction in check 6 that Mushroom Observer is already named there without a licence text.
